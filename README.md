# auto-change-effort

Claude Code のメインスレッドの effort を、依頼ごとに自動で選ぶ mod です。
依頼を Haiku に読ませて low / medium / high / xhigh のどれかを選び、そのターンの effort をその段階に書き換えます。
重くない依頼で effort を下げ、クレジットと時間を節約するのが目的です。

## 何をするか

1. ターンの始めに、依頼の本文(先頭 1000 字)と前の回答の末尾(400 字)を Haiku に渡し、段階を1つ選ばせる
2. そのターンの各ステップで、effort を選ばれた段階に書き換える(effort を取らないモデルのときは触らない)
3. ターンが長引いたら、次のターンを1段上げて始める
   - 長引いた:往復が 10 回を超えた、またはツールのエラーが累計 2 回出た
   - 上げるのは1段まで、上限は xhigh。そのターンの途中では上げない(途中で上げても、そのターンには効かないため)
4. 次のときは Haiku を呼ばず、前のターンの段階のまま進める
   - Haiku の返事が 4 秒以内に来ない・読めない(初回なら書き換えず、設定どおりの effort)
   - バックグラウンドの作業の完了通知(`<task-notification>` で始まる入力)のターン
5. サブエージェントのターンには触らない

## 使い方

```
/auto-change-effort on    # 自動切り替えを始める(入れた直後は on)
/auto-change-effort off   # やめる。off の間は effort に触らない
/auto-change-effort       # 今の状態を表示する
```

ステータスラインに今の状態が出ます。

| 表示 | 意味 |
|---|---|
| `effort: medium` | このターンは medium で動いている |
| `effort: high (+1)` | 前のターンが長引いたので、判定より1段上げている |
| `auto-change-effort: off` | 自動切り替えは off |

on / off は次のセッションにも残ります。

`/effort` で自分で決めたいとき(max を使いたいときなど)は、先に off にしてください。on の間は、この mod が毎ターン effort を書き換えます。

## 判定の表

Haiku には次の基準を渡しています。2つの段階で迷ったら低い方を選ばせます(足りなければ、長引いたときに次のターンで上がるため)。

| 段階 | どんな依頼か |
|---|---|
| low | 用語・仕組み・使い方を聞くだけの質問/あいさつ・お礼・短い相づち/手順が決まった短い作業(コミット、ファイルの移動・名前の変更など) |
| medium | コードの説明・調べもの/差分のレビュー/エラー文が出ている不具合の原因調査/範囲がはっきりした小さな変更 |
| high | 原因の手がかりがない不具合(たまにしか起きない、エラーが出ない)/設計案の比較・あいまいな要件の整理/プロジェクト全体から該当箇所を洗い出す/設計を根本から見直す・長時間ひとりで進める作業 |
| xhigh | プロジェクト全体の監査・移行/セキュリティ・データの消失・並行処理に関わる作業/直したはずなのに直らない不具合 |

「2」「Bで」のように、前の回答の選択肢から1つを選ぶだけの短い返事は、返事そのものではなく、選ばれた選択肢の作業の重さで判定します。選択肢は前の回答の末尾 400 字から読むので、それより前にある選択肢は Haiku から見えません。

基準の文は [auto-change-effort/hooks/judge.ts](auto-change-effort/hooks/judge.ts) の `RULES` にあります。

## Haiku の判定にかかる分

Haiku を挟む分、毎ターン少し費用が増えます。

- Haiku を呼ぶのは、on の間の1ターンに1回(通知・入力の無いターンでは呼ばない)
- 1回あたり入力 約 580〜1,800 トークン、出力 3 トークン(作者の環境で1回測った値。判定基準の文が約 580 で、依頼と前の回答が長いほど増える)

節約になるのは、メインのモデルの考える量が減ったターンです。Haiku の入力トークンは、メインのモデル(Opus など)の出力トークンより単価が低く、effort を下げると出力トークンが大きく減ります(作者の試しでは、同じ問題で low が 140、xhigh が 708 トークン)。

効いているかは、次で見分けられます。

- 元の effort の設定より低い段階(`effort: low` や `effort: medium`)がステータスラインに多く出ていれば、効いている
- 元の設定がもともと low なら、この mod は段階を上げることしかないので、節約にはならない

なお、作者が試した範囲では、この mod が呼んだ Haiku の分はセッションの費用の記録に載りませんでした。料金は Anthropic の料金ページで確かめてください。

## やらないこと

- max は選ばない。使いたいときは off にして `/effort max`
- on の間、`/effort` で決めた値は効かない(毎ターン書き換えるため)
- サブエージェントの effort は扱わない
- 判定の当たり外れの記録・評価はしない
- 段階の下限(「この作業中は medium 以上」など)は設けない。下げるときは一気に下げる
- 「OK」「お願いします」のような同意の返事に専用の扱いはない
- AskUserQuestion で答えたあとに判定し直すことはしない

```
claude plugin marketplace add AndoYuto87/auto-change-effort
claude plugin install auto-change-effort@auto-change-effort
```

リポジトリの直下で:

```
claude plugin validate ./auto-change-effort
claude plugin test ./auto-change-effort
```
